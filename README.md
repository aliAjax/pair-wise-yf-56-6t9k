# pair-wise-yf-56 网络安全事件响应作战室

## 源提示词摘要
值班人员接收告警，分析人员补充资产和影响范围，响应负责人批准隔离、封禁或恢复动作，法务和公关维护对外口径。系统展示实时事件时间线、子事件、审批、证据和责任人；高优先级动作双人确认，敏感内容按角色显示，并支持只读演示模式。

## 技术栈
Next.js 15 + TypeScript + App Router + shadcn/ui 本地组件 + Zustand + TanStack Query + React Hook Form + Zod + next-intl + date-fns + dnd-kit。

## 已实现闭环
- 主事件、子事件、处置动作和实时时间线。
- 子事件创建、动作审批、双人确认和执行状态流转。
- 角色权限控制、敏感内容遮蔽、只读演示模式。
- dnd-kit 调整处置优先级、TanStack Query 实时连接检查和 Zustand 持久化。

## 离线交班与事件版本合并
- 事件带 `version`、动作带修订号 `rev` 与批准时的事件上下文（级别 + 影响资产指纹）。
- 断网时审批、执行、子事件、级别/资产变更照常本地生效并进入待同步队列；回网后按三方合并（共同基线 / 本班次 / 对端快照）整合。
- 同一动作被两个班次同时改过时双方版本都保留、动作冻结，仅响应负责人可裁决，未采用版本永久留档。
- 事件级别或影响资产变化后，未执行动作的旧批准失效、回到待复核；已执行动作不回退。
- 隔离动作必须两个不同角色确认；演示模式与访客（viewer）的所有写入均被拒绝。
- 合并按操作幂等键 + 角色去重双重保证：整体失败（快照损坏 / 跨事件）不写入，待办与快照保留可重试，重试不会重复写入审批。
- 无版本号的历史持久化数据在 store v2 迁移中补成初始版本 v1，旧字符串审批升级为结构化记录。

## 测试

```bash
node scripts/run-tests.cjs
```
- `lib/sync.test.ts`：合并引擎 10 组规则（双角色确认、冲突留档、幂等重试、旧数据升级等）。
- `lib/store.test.ts`：断网记录 → 回网合并冲突 → 负责人裁决 → 失败保留重试 → 级别失效 → 持久化的全链路集成。
